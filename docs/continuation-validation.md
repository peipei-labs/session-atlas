## 本轮修复

- 为待续写入单独提供 256 KiB 请求空间，支持字段限制内的长中文卡。
- 关闭和恢复不再排在无关库存任务后面；请求断开或准备超时后，不派发尚未执行的动作。恢复额外的进程占用核验使用独立准备时限。
- 每批库存处理完后让排队请求执行，避免持续追新造成恢复检查饥饿；同时检查归属是否在处理期间变化。
- 将逐 PID 的多次 `lsof` 合并为一次批量查询，保留按 PID 的身份判定与失败处理，并限制只读子命令耗时。

## 2026-09-28：登记后延迟补色

保存了待续或收藏、但尚未获得分屏标记的线程，会在后续清单唯一识别原线程后重新尝试标色；服务重启后同样检查已保存卡片。每个线程及分屏进程身份最多尝试两次 profile 写入，成功后不随清单刷新重复写入。应用前重新核对在线状态、整个清单身份和收藏是否仍然存在；多实例、隐藏分屏和无法核验身份的线程不标色。

回归覆盖登记时未关联后恢复、纯收藏、重复实例、移除卡片、服务重启，以及核验期间移除卡片的并发情况。

本机另发现共享 Codex daemon 持有线程 writer lock，而前台 TUI 不持有 rollout 文件。现有只读信息不能把该 daemon 的多个线程唯一映射到某个 TUI；线程 shell snapshot 中的 iTerm session ID 也可能属于旧分屏。因此本次修复不根据标题、cwd 或旧环境变量推断关联。此类线程的自动关联仍待可靠的客户端映射接口，补色重试本身不能解决该限制。

## 2026-09-28：显式纠正已迁移线程的恢复目录

单卡 `POST /api/handoffs/:id/resume` 和 `POST /api/recoveries/:id/open` 可接受可选 `cwd`。用户明确选定的新目录通过现有目录限制校验、原线程身份与 writer 检查后，原子保存为原卡的 `cwd` 和 `cwdOverride`，再交由现有桥接恢复同一个线程。无参数恢复与批量恢复继续使用保存的纠正目录；未设置纠正目录的卡片仍采用原线程最新目录。已打开的线程仍直接聚焦，不能用这个参数更改运行中线程的目录。

原卡的待续、收藏和标签保持不变，不改写原始会话历史。回归测试覆盖旧目录已删除、新目录超出允许范围、首次桥接失败后目录纠正持久化，以及后续无参数恢复。协议检查及完整检查通过：609 项 Vitest、98 项 Python、54 项 helper，另有类型、shell 和构建检查。
