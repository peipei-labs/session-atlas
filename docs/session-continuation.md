# 待续、收藏与原线程恢复

有后续工作但暂时不能继续的线程，可以先登记到「待续」，再关闭分屏释放进程内存；需要继续时，从待续卡回到精确的原 Codex 线程。没有待办但值得以后参考的线程，可以明确收藏到「可能有用」。已完成且不需要保留的线程照常关闭，不创建卡片。「最近关闭」仍是短期恢复历史。

## 日常使用

1. 原线程推进工作，确实进入已经约定的等待时间、等待条件、待补充要求或稍后继续时，由 `$session-atlas-handoff` 登记简短交接信息。也可以明确说「暂存这个线程」。
2. 在目标 iTerm2 分屏按 **⌃⌥⌘B**（Control + Option + Command + B），或在 Session Atlas 使用「暂存并关闭」。已登记且身份明确、当前可以安全关闭时，保存恢复位置后调用 iTerm2 原生关闭。该操作只针对选中分屏。
3. 没有待续或收藏时，快捷键打开面板供查看和登记；可以选择「待续」或「可能有用」，不会自动给所有关闭记录创建卡片。关联不唯一、保存失败、线程正在执行或工作需要维持当前进程运行时，保留分屏并说明原因。
4. 「待续」中的「继续原线程」会定位仍运行的原分屏；线程已关闭时，在原窗口新建 Tab，原窗口已不存在则新建窗口，使用保存的工作目录和精确 session ID 恢复。整窗口恢复继续使用「窗口布局」。
5. 原线程继续工作时读取并更新原卡，复用已有事项，不需要再登记一张；事项达到验收要求后标记完成，用户取消后标记取消。没有待续事项的卡退出待续列表，已有收藏继续保留。也可以用卡片的「完成」按钮手动更新单项。

「待续」和「可能有用」都按位置分成「待恢复」「已打开」「位置待核对」。打开卡片后，等服务确认原线程已出现，卡片自动移到「已打开」；关闭确认后回到「待恢复」，不删除收藏或把事项标记完成。位置还不能确认时保留在「位置待核对」，不会把它误当成已关闭。搜索和标签筛选同时作用于这些分组。

登记卡片成功后，或从卡片打开、回到唯一的原线程时，确认关联的 iTerm 分屏会显示紫色 Tab，并在项目名下方显示「Atlas · 已保留」副标题。这项分屏标记不修改主标题；已有副标题会保留，并追加这段标记。它表示该线程仍有待续或收藏；待续的最新进展是否已登记，关闭时仍会再次检查。登记时分屏不在线、恢复尚未关联、只打开了 shell、同一线程有多个实例时不显示，之后通过卡片打开或回到原线程时会重新核验补上。普通蜂窝定位或手动打开不自动添加这个标记。

一个 Tab 有多个分屏时，Tab 颜色和副标题跟随当前选中的分屏，不代表其他分屏也已保留；拆出的新分屏不会因为继承配置而被当作已保留。完成所有待续且没有收藏，或删除卡片后，会清除标记并恢复原来的颜色和副标题；你后来手动改过的设置会保留。旧版紫色 Tab 或大水印会在重新核验原线程后更新为此样式，原有角标或你后来编辑的文字会保留。关联暂时无法核验时先清除显示，重新确认后再显示。

看到标记后仍使用 **⌃⌥⌘B** 或卡片关闭按钮。普通关闭按钮和 **⌘W** 没有新增保存或拦截动作。

「尚未关联到唯一的线程」只针对本次快捷键选中的分屏，不代表其他待续卡保存失败。点击「知道了」「返回列表」或退出面板会结束查看这个目标；重新打开面板或刷新页面不会带回已退出的旧提示。需要再次检查该分屏时，在原分屏重新按快捷键。

蜂窝和工作台直接显示该原线程的「未登记」「待续 N 项」「已收藏」或待续已完成／已结束状态；身份未能核验时显示「待核对」。工作台的「稍后再看」只调整关注顺序，需要保留后续事项时仍使用待续登记。

待续和最近关闭中的打开按钮会写明已有位置，例如「回到窗口 2 · Tab 5 · 分屏 3」。同一线程在多处打开时，先选择已有位置；没有现有位置时才请求恢复，服务仍会再次检查是否有其他实例。最近关闭的普通线程也能这样打开，不要求先登记待续或收藏。复制命令保留为手动备用方式。

## 线程标签

标签用于按技术、主题或具体任务查找线程，例如 `Python`、`React`、`页面测试`。原线程使用 `$session-atlas-handoff` 时，根据实际工作填写少量标签；你也可以在工作台、待续／收藏或最近关闭卡片中增删。已有标签会保留，不从同目录的其他线程猜测本线程的主题。

搜索框包含标签，顶部标签筛选支持多选，表示同时具备所有已选标签。标签旁的数量按原线程计数，同一线程在多个分屏打开只算一次。标签不改变状态颜色，也不产生待续或收藏。

标签按原线程 UUID 独立保存在本机 `state.json`；关闭、换分屏和恢复时沿用。普通恢复历史清理不删除标签；它也不会仅因为有标签就延长普通恢复历史。旧线程再次被识别时会重新显示自己的标签。未关联到唯一原线程的分屏不能标记。

原线程脚本用 `tags` 读取，用 `tag` 从标准输入接受 `{"add":["标签"],"remove":["要移除的标签"]}`。只提交此次增删，避免多个窗口修改时覆盖其他标签；写入后读取核对。每个线程最多 12 个标签，每个最多 40 个字符，大小写或全角写法相同的标签会合并。接口为 `GET /api/threads/:sessionId/tags` 和 `PATCH /api/threads/:sessionId/tags`，与待续卡接口独立。

## 可能有用

打开底部「待续 / 收藏」，切换到「可能有用」。选择已有的原线程，填写**主题**和**保留原因**即可收藏，不要求下一步、等待条件或日期。也可以在原线程说：

> 使用 $session-atlas-handoff，把这个线程收藏为“可能有用”，原因是这里的排查方法以后可以参考。

收藏后仍使用 **⌃⌥⌘B** 或卡片的关闭按钮；恢复时使用「回到原线程」。只保存精确原线程的恢复信息和简短主题、原因，不复制完整对话。收藏是用户明确选择的保留方式，不会由 skill 自动推断。

只有收藏、没有未完成事项的卡，可以多次打开查看后直接再次关闭，无须每次重写主题和原因。若同一张卡还有未完成事项，开始新一轮工作后仍须更新原卡，确认最新进展已保留。正在执行、身份不唯一或确实需要维持进程运行时，关闭操作仍会保留分屏。

「待续」和「可能有用」分别计数。一张线程卡可以同时包含两种内容：完成或结束待续保留收藏，取消收藏保留待续。只有收藏的卡片不会显示到期提示或完成按钮。可按主题、原因搜索，最近关闭列表里的原线程也可从收藏编辑器选择。

收藏还会尝试给本机 Codex daemon 中的原线程名称加 `🔖 ` 前缀，例如 `🔖 核查 mobile 日志`。这是 Codex 原线程的名称，恢复列表也会显示；Codex 自己更新所在终端的标题，因此不依赖 Atlas 找到对应分屏。只有待续、没有收藏时不添加这个图标。自定义终端标题若未包含线程名称，图标不会出现在 Tab 上；紫色 Tab 仍按前面的分屏身份规则处理。

Atlas 在改名前保存原名和加标记后的名称，取消收藏时只恢复仍然匹配的名称。后来手动改名时，本次同步会保留新名字；收藏仍在的情况下，下次明确保存或打开可以给新名字加前缀。daemon 不可用、没有有效线程名称或改名失败都不会撤销已保存的卡片。服务启动不会批量修改旧收藏的名称。

写入响应超时不代表没有保存。原线程会保留分屏，并用一次只读查询核对原卡；只有读回的事项和时间依据一致才确认保存结果，否则说明结果仍未确认，不盲目重复写入。

本机保留原有 **5 秒 iTerm2 关闭撤销期**。关闭后要等撤销期结束，进程才可能真正退出；Buried Sessions 只是隐藏分屏，不能作为释放内存的依据。是否释放以目标进程退出为准，macOS 的 swap 数字不一定立即下降。恢复不还原终端滚屏、未提交的输入或原 shell 进程状态。

## 分类与时间

一张线程卡可以有多个不同类型的后续事项。颜色是辅助标记，卡片同时显示文字标签。

| 类型 | 色标 | 卡片说明 |
| --- | --- | --- |
| 等时间 | 蓝色 | 实际起算事件、待核验时间 |
| 等条件 | 紫色 | 需要成立的条件 |
| 待补充要求 | 橙色 | 还缺什么信息 |
| 稍后继续 | 灰色 | 恢复后的下一步 |

时间按带时区的绝对时间保存，界面默认使用 `Asia/Shanghai`。例如「上线后 24 小时核验」以已知的实际上线时间计算，不从登记或关闭时间起算。依据不足时显示「时间待确认」。不同事项可以各有自己的起算事件和时间。

到期事项在看板置顶并显示「该核验了」，不发送系统通知、不自动恢复或执行，也不会自动标记完成。外部条件由用户或原线程更新，不自动轮询外部服务。

## 登记方式的试行选择

**2026-09-09 采用的第一版选择是主动登记试行**：只收集已经约定、当前确实必须等待的后续工作。排除已完成事项、可选建议、未经采纳的设想和普通关闭。仍能自主推进的已授权工作应先继续，不能为了生成交接记录而提前停止。

候选方案是「只有用户说暂存才登记」。这一候选方案仍用于比较，并未与主动登记做成两个可切换模式。后续根据真实的误收、漏收和操作负担，再由用户决定是否切换；第一版不增加模式设置，也不把这次试行当成永久规则。

通过 Session Atlas 恢复的终端线程，会在该次启动参数中加载原卡维护提示：恢复或压缩上下文后提供维护规则，每次用户发消息时给一条简短提醒。提示只要求原线程利用已有上下文执行 skill 的短时本地脚本，不增加摘要模型、网关或常驻 MCP。仅打开窗口不会启动一轮模型工作；开始处理下一条消息时才读取原卡，本轮结束前根据真实进展更新并读回核对。是否完成仍由原线程根据验收结果判断，关闭或回合结束不直接改成完成。

这个入口使用本机 Codex 的 `SessionStart` / `UserPromptSubmit` Hooks，只有本次恢复进程中的两个自有命令被授权；不修改全局配置、不替换用户原有指令或授权其他 Hooks。提示失败不会阻塞用户工作。它不是关闭时强制执行的回调，卡片操作仍保留手动入口和保存失败提示。

已经开着的旧线程和手动执行普通 `codex resume` 的线程不会被注入输入，也不会自动获得这次启动参数；它们可以直接调用 `$session-atlas-handoff` 使用更新后的原卡规则，无须为了使用 skill 重开。下次通过 Session Atlas 恢复时会自动带上维护提示。主动创建全新待续仍按前面的约定条件，快捷键在缺少登记时保留分屏。

## 保存内容与接口

卡片只保存简短交接说明、后续事项、时间依据、收藏主题和原因，以及恢复所需的 session ID、cwd 和窗口位置，不复制完整对话、终端输出或凭证。内容保存在本机恢复记录中，通过本机 API 和事件更新显示，不写入日志或浏览器持久存储。仍有待续事项或收藏的卡及必要恢复信息不受普通 30 天 / 200 条恢复历史清理影响；待续已结束且收藏已取消后恢复普通历史保留规则。

安装程序将仓库中的 `skills/session-atlas-handoff` 链接为 `~/.codex/skills/session-atlas-handoff`。脚本可以在原线程使用的项目子目录或 worktree 中运行，线程身份来自 `CODEX_THREAD_ID`，保存和恢复目录由服务读取唯一原线程记录核验，不需要先切回原启动目录。脚本仅连接 `127.0.0.1:4317`；自定义本机端口使用数字型 `SESSION_ATLAS_PORT`。

本地接口为 `GET /api/handoffs/:sessionId`、`PUT /api/handoffs/:sessionId` 和 `DELETE /api/handoffs/:sessionId`。读取和写入返回包含可选 `handoff` 的恢复记录；未知恢复记录读取返回 404，删除成功返回 204。脚本的 `read` 将没有卡片表示为 `handoff: null`；`write` 从标准输入读取内容并补充运行环境中的 cwd 和 `source: "thread"`，不接受调用者传入其他线程身份。服务对原线程登记采用记录中核验出的最新 cwd，并检查该目录有效且允许使用；`source: "user"` 的手动登记仍要求提交目录与原线程一致。

每次写入前先读取现有卡片，保留稳定事项 ID 和用户修改，将有证据的进展合并回同一张卡。服务负责更新时间和根据实际起算事件计算到期时间。完整字段和调用示例见 [handoff skill](../skills/session-atlas-handoff/SKILL.md)。

收藏使用可选的 `reference: { title, reason }`，只有收藏时 `items` 可以为空。更新时省略 `reference` 保留现有收藏，显式传 `null` 才取消收藏；`DELETE` 删除整张卡的待续与收藏，不用于仅取消其中一种。

`POST /api/handoffs/:sessionId/title-marker` 接受空对象 `{}`，按卡片的现有收藏状态补加或撤销名称标记，不改卡片正文、版本或标签。返回 `applied`、`cleared`、`unchanged` 或 `unavailable`。普通保存和通过 Atlas 打开也会尝试同步。已关闭但未归档的线程也能保存名称，之后打开时显示；daemon 离线或线程已归档时暂缓，不自动恢复或解档。尚待撤销的标记会保留原名记录，直到成功撤销或确认名称已由用户修改。

已验证的容量、异常场景和本机关闭恢复结果见 [待续功能验收记录](continuation-validation.md)。
