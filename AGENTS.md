# Session Atlas project rules

- Keep the service bound to `127.0.0.1`; do not add remote exposure, cloud sync, authentication products, team features, or public distribution unless the user explicitly requests them.
- Existing iTerm2 sessions remain input-read-only. The installed controller may set or clear only its own session-local future-start command for a uniquely linked Codex pane, and must not replace an unrelated custom command. After an explicit user close action, the bridge may natively close that exact pane only after its pending handoff or explicitly requested bookmark and recovery metadata are saved and its identity and idle state are rechecked. Preserve iTerm's close Undo period. The bridge may enumerate and focus exact sessions, restore selected closed layouts, and resume a saved thread in a new tab or window with an exact recorded Codex resume command; it must never call `async_send_text`, scrape terminal screens, synthesize keystrokes, or directly kill terminal/agent processes.
- Only Codex threads created or resumed through Session Atlas's own App Server client may expose send, steer, interrupt, approval, or answer actions. Keep all other actions capability-gated and fail closed.
- For a saved thread explicitly opened through Atlas, or immediately after its handoff card is successfully registered, the bridge may customize only that exact pane's Tab color and subtitle after original-thread identity is verified, and remove a legacy badge only while it remains Atlas-owned. Keep marker provenance and profile backups in its own session-local variable, restore only still-owned fields, and clear inherited split markers. Never modify global profiles or treat a visual marker as authorization to bypass close checks.
- For a thread with pending handoff items or an explicit bookmark, Atlas may add its own `🔖 ` prefix to the exact Codex thread name through the local daemon. Save the original and applied names before renaming, recheck the current name before each write, and restore only the still-owned name once no pending items or bookmark remain. Never use a title marker as evidence of pane identity or permission to control a thread.
- Do not add automatic orphan cleanup, broad process reaping, or global Codex/iTerm configuration changes beyond the owned continuation skill and the explicitly requested Session Atlas shortcut.
- Persist attention, recovery metadata, and bounded handoffs explicitly submitted by the original thread or the user: exact Codex session IDs, cwd, stable terminal titles, profiles, window/tab/pane location, concrete follow-up items with their time or condition basis, and bookmark topics and reasons. Save bookmarks only on an explicit user request; never classify optional suggestions or ordinary completed threads as bookmarks automatically. Do not write raw prompts, transcripts, terminal contents, credentials, approval payloads, arbitrary commands, or command output into Session Atlas state files, browser storage, or logs. Handoff contents may appear in local API responses and React memory, but not logs or browser storage. The local recently-closed view may read and hold only bounded first/latest user-request excerpts in process and React memory; never persist those excerpts or include them in the event stream.
- `docs/design/design-system.md` and the implementation in `src/client/` are the current visual source of truth; Preserve the honeycomb board, attention strip, modal workbench, recovery shelf, and window-layout shelf. Show original-thread handoffs in the continuation shelf; do not generate archive summaries, fake progress percentages, ETA, or dependencies. Closing a terminal or ending a model turn never means its follow-up work is complete.
- Before handing off changes, run `npm run protocol:check` and `npm run check`. Live focus or layout-restore tests must use disposable iTerm2 sessions and must not send input into existing sessions.
- Record exact file, commit, and license provenance in `THIRD_PARTY_NOTICES.md` before copying upstream source code.
